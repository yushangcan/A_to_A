## 2. 产品概述

A to A 面向餐饮、美业、实体零售、电商、教育培训、家政、摄影、健身等需要线上推广的中小商家，帮助商家将一次活动信息转化为多种平台可使用的营销内容。

商家只需要输入店铺信息、活动内容、产品或服务信息以及图片描述，系统即可基于统一的品牌档案，生成小红书笔记、短视频脚本、朋友圈文案和评价管理话术，并在发布前完成事实、风格和平台格式校验。

产品的核心不是简单复制同一段文案，而是：

```text
统一品牌信息
    -> 统一活动事实
    -> 多场景内容生成
    -> 平台和合规校验
    -> 人工确认
    -> 复制、导出或发布
```

## 3. 商业定位

### 3.1 目标客户

- 没有专职运营人员的个体商家。
- 有运营人员但内容产出效率低的小型门店。
- 需要同时维护多个平台的连锁门店或小型品牌。
- 需要持续推广商品、服务和活动的电商小店。

### 3.2 典型行业

产品核心能力不绑定某一个行业，行业差异通过行业配置包实现。

| 行业 | 典型推广对象 | 额外业务字段示例 |
| --- | --- | --- |
| 餐饮 | 菜品、套餐、开业、节日活动 | 口味、套餐、用餐人数、预约方式 |
| 美业 | 护理、造型、体验卡 | 服务时长、适用人群、技师、预约方式 |
| 实体零售 | 商品、到店活动、换季促销 | 库存、自提、门店位置、使用场景 |
| 电商 | SKU、优惠券、直播和促销 | 规格、链接、物流、售后、发货时间 |
| 教培 | 课程、试听、招生活动 | 课程周期、适用年龄、上课方式 |
| 家政 | 保洁、维修、护理服务 | 服务范围、计费方式、人员资质 |

### 3.3 产品差异化

- 商家只输入一次活动信息。
- 系统保存并复用品牌风格。
- 不同平台输出不同内容形态，而不是机械复制。
- 自动校验价格、时间、地址、联系方式等关键事实。
- 生成结果可以人工编辑、复制、导出或后续发布。
- 保存活动和内容历史，为后续效果分析提供数据基础。

## 4. 产品目标

### 4.1 MVP 目标

用户能够完成以下闭环：

1. 创建商家和品牌档案。
2. 创建一次营销活动。
3. 选择目标内容类型。
4. 并行生成四类营销内容。
5. 查看校验结果和警告。
6. 修改并确认内容。
7. 一键复制、导出或模拟发布。
8. 查询本次活动的生成和发布记录。

### 4.2 非目标

MVP 暂不实现以下内容：

- 不承诺所有平台都支持真实 API 发布。
- 不使用网页登录自动化绕过验证码或平台限制。
- 不自动编造客户评价、消费经历或客户见证。
- 不在第一版实现完整视频生成和自动剪辑。
- 不在第一版实现复杂 RAG 知识库。
- 不在第一版引入 Redis、消息队列或微服务集群。
- 不在第一版实现广告投放、订单交易和 CRM。
- 不在第一版根据平台数据自动修改商家经营策略。

## 5. 核心用户和使用场景

### 5.1 商家老板

商家老板通常不擅长写文案，只希望输入“我有什么活动、卖什么、给谁、多少钱”，然后得到可以直接使用的内容。

### 5.2 店铺运营人员

运营人员需要批量生成不同平台的内容，并希望保留品牌统一性，减少重复修改和格式转换。

### 5.3 典型场景

```text
一家美容店推出 99 元补水护理活动，活动持续到月底。
老板输入服务内容、价格、目标人群和图片描述。
系统生成：
1. 小红书种草笔记
2. 抖音或视频号短视频脚本
3. 朋友圈活动文案
4. 真实评价邀请和差评回复草稿
```

## 6. 核心概念

### 6.1 商家 Merchant

系统中的租户主体，可以拥有一个或多个店铺、品牌档案和平台账号。

### 6.2 品牌档案 Brand Profile

保存品牌长期不变或低频变化的信息，包括定位、受众、语气、核心卖点、禁用词和服务承诺。

### 6.3 行业配置 Industry Profile

定义某个行业的专用字段、术语、内容模板和校验规则。行业配置不应修改核心业务代码。

### 6.4 活动 Brief

保存某一次活动的具体信息，包括商品或服务、时间、价格、规则、目标和素材。

### 6.5 Agent Task

由中心调度器创建的子任务，例如生成小红书笔记或短视频脚本。

### 6.6 Content Artifact

Agent 生成的具体内容产物，可以被编辑、校验、审批、导出和发布。

### 6.7 Publish Task

将已确认的内容复制、导出、模拟发布或通过官方 API 发布的任务。

## 7. 用户流程

### 7.1 首次使用

1. 用户注册或登录。
2. 创建商家工作区。
3. 选择行业。
4. 填写品牌档案。
5. 配置店铺地址、联系方式和常用行动引导。

### 7.2 创建活动

1. 输入活动名称。
2. 填写商品或服务。
3. 填写活动时间、价格和规则。
4. 选择目标客户和推广目标。
5. 上传图片或填写产品图描述。
6. 选择要生成的内容类型。

### 7.3 生成和审核

1. 系统整理商家输入。
2. 提取关键事实并锁定约束。
3. 中心调度器创建 Agent 任务。
4. 四个 Agent 并行生成内容。
5. 系统执行事实、平台、风格和合规校验。
6. 不合格任务最多自动重试两次。
7. 用户在内容工作区预览和修改。
8. 用户确认最终版本。

### 7.4 发布和导出

用户可以选择以下模式：

```text
SIMULATED       模拟发布并生成虚拟发布记录
MANUAL_EXPORT   导出平台专属内容，由用户手动发布
OFFICIAL_API    使用已经授权的官方平台接口
```

不同平台的任务独立执行。一个平台失败不影响其他平台已经成功的结果。

## 8. 功能需求

### FR-01 商家和工作区

优先级：P0

- 支持用户注册和登录。
- 支持创建商家工作区。
- 支持保存店铺名称、行业、地址、联系方式和简介。
- MVP 可以暂时限制一个用户一个工作区。
- 后续支持多个员工和权限分工。

### FR-02 品牌档案

优先级：P0

支持维护以下字段：

```text
品牌定位
目标客户
品牌语气
常用表达
禁用词
核心卖点
服务承诺
价格表达方式
默认行动引导
真实案例和证明材料
```

品牌档案必须在生成任务中作为统一输入，不能由每个 Agent 自行重新推断。

### FR-03 行业配置

优先级：P0

- 支持选择行业。
- 支持加载行业专属输入字段。
- 支持行业专属提示词和示例。
- 支持行业专属禁用词和校验规则。
- 支持后续新增行业，而不修改调度器核心逻辑。

### FR-04 活动管理

优先级：P0

- 创建、编辑、保存和删除草稿活动。
- 保存活动名称、商品或服务、价格、时间、规则和目标客户。
- 支持上传或关联图片素材。
- 保存活动历史版本。
- 允许基于历史活动复制创建新活动。

### FR-05 中心调度器

优先级：P0

- 将用户输入整理为结构化 Campaign Brief。
- 提取价格、日期、商品名称、地址和联系方式等关键事实。
- 根据用户选择创建 Agent Task。
- 并行调用多个 Agent。
- 保存任务状态、耗时、重试次数和错误信息。
- 汇总结果并进入统一校验流程。

中心调度器不负责直接生成所有内容，也不允许子 Agent 无限互相调用。

### FR-06 小红书 Agent

优先级：P0

输出：

- 2 至 3 个标题候选。
- 种草笔记正文。
- 开头吸引点。
- 封面文字建议。
- 图片使用顺序。
- 话题标签。
- 评论区互动引导。

### FR-07 短视频 Agent

优先级：P0

输出：

- 视频主题。
- 前三秒开场。
- 口播台词。
- 分镜文字。
- 拍摄动作和字幕。
- 视频标题和标签。
- 结尾行动引导。

短视频 Agent 只生成脚本和元数据，不负责生成视频文件。

### FR-08 朋友圈 Agent

优先级：P0

输出：

- 活动短文案。
- 熟人推荐风格文案。
- 客户通知文案。
- 海报配文。
- 限时活动版本。

MVP 只生成海报配文，不生成海报图片。

### FR-09 评价管理 Agent

优先级：P0

输出：

- 真实评价邀请。
- 售后回访话术。
- 差评回复草稿。
- 评价情绪和问题分类。
- 需要人工处理的投诉提示。

禁止生成虚假客户评价、虚构消费经历、虚构客户身份或未经商家确认的赔偿承诺。

### FR-10 内容校验

优先级：P0

#### 事实校验

- 价格一致性。
- 活动时间一致性。
- 商品或服务名称一致性。
- 地址和联系方式一致性。
- 活动规则一致性。

#### 平台校验

- 标题长度。
- 正文长度。
- 标签数量。
- 图片和视频要求。
- 平台必填字段。

#### 风格和合规校验

- 是否符合品牌语气。
- 是否包含禁用词。
- 是否存在夸大承诺。
- 是否出现输入中不存在的事实。
- 是否需要人工确认。

### FR-11 内容工作区

优先级：P0

- 按平台查看生成结果。
- 支持标题、正文、标签和分镜单独编辑。
- 展示事实来源和校验警告。
- 展示原始版本和修改后版本。
- 支持重新生成单个平台内容。
- 支持用户确认单个平台或全部内容。

### FR-12 导出和模拟发布

优先级：P0

- 一键复制标题、正文和标签。
- 导出 Markdown、TXT 或 JSON 内容包。
- 模拟生成平台发布记录。
- 保存模拟发布时间、平台、内容版本和虚拟链接。
- 支持只重试失败的平台任务。

### FR-13 真实平台发布

优先级：P1

- 只接入官方允许的 API。
- 平台账号通过授权流程接入。
- Token 加密保存。
- 每个平台独立记录发布状态。
- 记录外部平台返回的 ID、链接和错误信息。

真实发布能力必须按平台逐个验证，不能假设四个平台都拥有相同的公开发布接口。

### FR-14 内容历史

优先级：P1

- 查询活动历史。
- 查询每个 Agent 的生成版本。
- 查询用户修改记录。
- 查询模拟发布和真实发布记录。
- 支持复用历史活动。

## 9. Agent 输入输出协议

每个 Agent 统一接收：

```text
BrandProfile
IndustryProfile
CampaignBrief
TargetPlatform
OutputSchema
HardConstraints
```

每个 Agent 统一返回：

```json
{
  "agent_type": "xiaohongshu",
  "platform": "xiaohongshu",
  "title_candidates": [],
  "content": "",
  "tags": [],
  "assets": [],
  "facts_used": [],
  "warnings": [],
  "requires_human_review": false
}
```

模型不能直接把结果写入最终发布记录。结果必须先经过解析、校验和人工确认。

## 11. 系统架构

### 11.1 MVP 逻辑架构

```text
前端管理台
    |
    v
Go Gin API
    |
    +-- 商家和品牌模块
    +-- 行业配置模块
    +-- 活动模块
    +-- 中心调度模块
    +-- Agent 模块
    +-- 校验模块
    +-- 审核模块
    +-- 导出和模拟发布模块
    +-- 审计模块
    |
    v
MySQL + 本地素材存储
```

MVP 使用模块化单体。四个 Agent 是四个逻辑模块，不需要立即拆成四个独立服务。

### 11.2 后续 AI 服务

后续可以把模型调用独立为 Python FastAPI 服务：

```text
Go 调度器
    |
    v
Python AI Gateway
    |
    +-- Prompt 模板管理
    +-- 模型调用
    +-- 结构化输出解析
    +-- 模型结果评估
```

Go 仍然负责业务数据、任务状态、权限和审核；Python 只负责 AI 能力。

### 11.3 后续任务系统

第一版可以使用 Go 协程和数据库状态完成并行生成。后续任务量增加时再引入 Redis 或消息队列，解决：

- 任务持久化。
- 服务重启后的任务恢复。
- 多实例消费。
- 限制模型调用并发。
- 失败重试和延迟任务。

## 12. 数据库设计

核心表：

```text
users
merchants
brand_profiles
industry_profiles
campaigns
assets
agent_tasks
content_artifacts
approval_records
publish_tasks
audit_logs
```

关键关系：

```text
用户
  -> 商家工作区
  -> 品牌档案
  -> 多个营销活动
  -> 每个活动多个 Agent Task
  -> 每个任务多个 Content Artifact
  -> 审核后生成 Publish Task
```

行业数据采用“固定核心字段 + custom_fields JSON”模式。核心字段保持强类型，行业特殊字段放入 JSON，避免数据库完全失去结构。

## 14. 非功能需求

### 14.1 安全

- 商家数据按工作区隔离。
- 平台 Token 不明文保存。
- 不保存第三方平台密码。
- 上传文件校验文件类型和大小。
- 日志中不得输出 Token 和完整敏感内容。
- 记录关键操作审计日志。

### 14.2 稳定性

- 单个 Agent 失败不能影响其他 Agent。
- 每个 Agent 设置超时时间。
- 自动重试次数有限制。
- 支持只重试失败任务。
- 使用幂等键避免重复发布。

### 14.3 可解释性

- 展示内容使用了哪些活动事实。
- 展示校验失败原因。
- 保存原始版本、模型版本和用户修改版本。
- 保存每次生成的任务状态和耗时。

## 15. MVP 验收标准

满足以下条件即视为 MVP 完成：

1. 用户可以创建一个商家工作区。
2. 用户可以填写一个通用品牌档案。
3. 用户可以选择餐饮、美业、零售、电商等行业。
4. 用户可以创建一条活动 Brief。
5. 系统可以并行创建四个 Agent 任务。
6. 四个 Agent 都能返回结构化内容。
7. 系统可以发现价格、时间、禁用词等错误。
8. 用户可以编辑和保存单个平台版本。
9. 用户可以确认全部内容。
10. 系统可以复制、导出或模拟发布。
11. 系统可以查询任务状态和历史记录。
12. 一个 Agent 失败时，其他 Agent 的成功结果不会丢失。

## 16. 产品指标

### 技术指标

- Agent 任务成功率。
- 平均生成耗时。
- 平均重试次数。
- 事实校验失败率。
- 平台格式校验失败率。
- 单次生成成本。

### 商业指标

- 从活动输入到可发布内容的平均时间。
- 商家最终采用率。
- 商家平均修改比例。
- 单个商家的月生成次数。
- 历史内容复用率。
- 用户留存和续费情况。

## 17. 风险和处理方案

| 风险 | 处理方案 |
| --- | --- |
| 模型编造价格、日期或卖点 | 锁定事实字段，并做程序化前后校验 |
| 生成虚假客户评价 | 改为真实评价邀请和真实差评回复 |
| 平台接口不可用 | 提供复制和手动导出能力 |
| 不同行业差异过大 | 使用行业配置包，不把行业逻辑写死在 Agent 中 |
| Agent 无限重试 | 设置最大重试次数和人工处理状态 |
| 多平台部分成功 | 每个平台独立任务和独立结果 |
| 四个服务维护复杂 | MVP 使用模块化单体，后续按负载拆分 |
| 自动发布触发平台风控 | 只使用官方授权接口，不使用绕过验证的自动化登录 |

## 18. 实施路线

### Phase 0：项目基线

- 初始化 Git 仓库。
- 建立 `docs`、`cmd`、`internal`、`web` 目录。

- 用户登录。
- 商家工作区。
- 行业选择。
- 品牌档案。

### Phase 2：活动模块

- 活动 Brief。
- 素材关联。
- 活动草稿和历史。

### Phase 3：Agent 生成模块

- 四个 Agent 接口。
- 结构化输入输出。
- 并行调度。
- 任务状态保存。

### Phase 4：校验和审核模块

- 事实校验。
- 平台规则校验。
- 风格和合规提示。
- 内容编辑和人工确认。

### Phase 5：导出和模拟发布

- 复制。
- 文本和 Markdown 导出。
- 模拟发布记录。
- 失败任务重试。

### Phase 6：扩展能力

- 行业配置包。
- 官方平台授权。
- 定时发布。
- 图片和海报生成。
- Python AI Gateway。
- Redis 或消息队列。
- 内容效果统计。
